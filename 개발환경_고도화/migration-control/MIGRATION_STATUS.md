# hoiBot RDB 이관 대시보드

이 문서는 운영자가 전체 이관 범위, 현재 Queue, 검증 상태와 다음 시작점을 빠르게 확인하는 대시보드다.
상세 복구 근거는 [CHECKPOINT.md](./CHECKPOINT.md), 기계 판독 상태는 [progress.json](./progress.json)을 기준으로 한다.

## 현재 상태

| 항목 | 현재 값 |
|---|---|
| 작업 상태 | 진행 중 |
| 작업 브랜치 | `feature/modernization` |
| 마지막 원격 확인 커밋 | `c261ad595408cab3e6a4b1186dba9b84bae01113` |
| DB 설계 | 31 migrations / 125 tables / 893 columns / 178 foreign keys |
| 시험 DB | `hoibot_schema_design` |
| 운영 데이터 적재 | 미실행 — 전체 기능 검증 후 마지막에 진행 |
| 운영 DB 변경 | 없음 |
| 현재 단계 | A-1 `/펫먹이조합` 구현 중 |
| 다음 재개 지점 | `/펫먹이조합` Application Service 구현 |

## 안전 조건

| 조건 | 상태 |
|---|---|
| 운영 `data/*` 원본 수정 금지 | 유지 |
| 운영 DB `hoibot` 합성 probe 차단 | 확인 |
| 시험 DB 반복 적재 | 확인 |
| 기존 사용자 미커밋 변경 보존 | 유지 |

| 운영 전 전체 시험 DB 초기화 | 예정 |
| 최종 fresh snapshot 전체 이관 | 미실행 |

## 갱신 규칙

- 기능 시작 시 상태를 `진행 중`으로 변경한다.
- 합성 DB와 parity가 통과하면 `검증 완료`로 변경하고 커밋을 기록한다.
- 실패 또는 미검증 항목은 완료로 표시하지 않는다.
- 실제 운영 데이터 전체 이관 전까지 운영 데이터 적재 상태는 `미실행`으로 유지한다.
