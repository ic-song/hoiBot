## 확인한 병목과 변경

- 추가된 매분 자동 작업은 금광만 처리할 때에도 분리 게시 복구의 회원+레이드 전체 파싱, 일반 회원 로드의 회원+운영 로그 파싱을 데이터 공통 잠금 안에서 실행했다. 정상 상태에서 회원2회+분리 레이드/로그 각각1회 읽기가 발생했다. 실제 단말의 느려짐을 실측한 확정 원인과는 구분한다.
- 전투 없는 금광 적립은 회원을 사용하지 않으므로 회원 로드·회원 분리 복구 검사를 생략하고 길드 데이터만 처리한다. 초기화/전투 예정 시각 도달 시 기존 분리 복구를 먼저 수행하고 bootstrap 회원을 읽는다. 시작 시 분리 복구는 그대로다. 복구를 제거하거나 손상 파일을 기본값으로 바꾸지 않는다.
- 한 번 확정한 tickNow로 회원 필요 여부와 전투 판정을 함께 처리한다. 금광 전용 게시3개/회원 포함 게시14개 복구 사본과 백업 정책은 그대로다.
- 길드전쟁 명령은 response가 이미 읽은 회원을 전달해 회원+분리 로그의 중복 로드를 제거했다. 길드 원본은 진입 시 새로 읽어 기존 신선도를 유지한다.
- saveJsonFile, loadJsonFile, recoverMemberSplitPublication, prepareGuildWarPublication, recoverGuildWarPublication, processGuildWars, resolveGuildWarMatch, settleGuildWarMines, runHowolMysteryEntry 본문 동일성을 확인했다. 추리소설·보상·전투 수식은 변경하지 않았다.
