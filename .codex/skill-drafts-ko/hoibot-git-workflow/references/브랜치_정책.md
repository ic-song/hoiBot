# 브랜치 정책

## 브랜치 역할

- `feature/prod`: 운영-facing 코드용 운영 브랜치
- `feature/hoi`: 운영 scripts가 사용하는 hoi-managed task branch
- `feature/workflow`: 문서, agent strategy, branch strategy, tools workflow 변경
- `feature/bugFix` 또는 요청된 bugfix casing: 버그 수정, 원인 분석, 최소 수정, 회귀 검증
- `main`: stable/reference branch이며 active production source로 가정하지 않는다.

## 최신성 규칙

특정 브랜치에서 작업을 시작할 때:

1. 대상 브랜치를 upstream 기준으로 업데이트한다.
2. `origin/main`을 대상 브랜치에 반영한다.
3. 최신화와 충돌 처리가 끝난 뒤 task edit을 시작한다.

이 흐름은 이후 충돌을 줄인다.
