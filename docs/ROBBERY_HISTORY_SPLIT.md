# 강탈 이력 분리 운영 안내

적용 버전: ver_2.646

운영자는 MAIN·Info 소스를 업로드하고 컴파일한 뒤 기존 관리자·MASTER 권한과 명령어방 조건으로 `/데이터정리`를 실행한다. 별도 초기 JSON 업로드는 필요하지 않다. 기존 운영 로그 복구 전용 응답이 나온 경우 복구 완료 후 한 번 더 실행하면 일반 정리와 강탈 이력 이전을 진행한다.

## 이전 결과

- 기존 `member_pet.json`의 강탈 배열을 모두 보존해 `miniPetRobberyHistory.json`으로 옮긴다.
- 최초 사본은 `miniPetRobberyHistory_legacy.json`에 보관한다. 재실행 때 덮어쓰지 않는다.
- 회원 파일에는 이전 완료 표시를 저장하고, 펫 파일의 기존 배열을 제거한다.
- 완료 안내의 `[강탈 이력 분리]`에서 추가 이전 건수와 회원 수를 확인한다.
- 재실행은 이미 옮긴 기록을 중복 추가하지 않는다. 동일 ID라도 내용이 다른 기록과 원래 동일 행의 중복 개수는 보존한다.
- 조회는 기존처럼 최근 50건을 최신순으로 표시한다. 기록은 삭제하지 않는다.

## 저장·복구

`miniPetRobberyPending.json`에는 회원·펫·이력의 작업 전 원문을 기록한다. 실패 시 기존 명령 트랜잭션에서 원복하며 중단 상태는 다음 MAIN 요청 또는 운영 재컴파일의 타이머 시작 전에 복구한다. 모든 복구 원문을 검증한 뒤 복구하며 초기 이전 당시 없던 이력 파일만 삭제한다. DEV 데이터와 복구는 `/sdcard/호이랜드_dev/`에서 처리한다.

자동일퀘는 강탈 이력을 반영해도 회원·펫 일괄 저장이 끝날 때까지 최초 복구 사본을 유지한다. Info는 복구 대기 중 부분 반영된 데이터를 출력하지 않는다.

완료된 별도 이력 파일이 없거나 손상됐을 때 빈 배열로 대체하지 않는다. 이전 표시 없이 같은 파일이 이미 존재해도 덮어쓰지 않는다. 외부 백업·복원 시 회원의 이전 표시, 펫, 이력 파일을 같은 시점의 세트로 보존한다. 분리 완료 표시가 유지된 상태에서 구형 펫 배열이 복원되었다면 `/데이터정리`로 잔류 기록을 대조·이전한다.

## 용량과 검증

2026-10-13 저장소 스냅샷의 복사본으로 검증한 결과 40계정의 5,168건이 원문과 동일하게 보존됐다. 펫 파일은 1,252,123 → 840,267바이트로 약 411,856바이트(32.9%) 감소하고, 별도 이력 파일은 411,445바이트다. 실제 운영 데이터의 감소량은 다를 수 있다. 원본 데이터 파일은 개발 과정에서 변경하지 않았다.

일반 명령은 별도 이력을 읽지 않는다. 기록 자체는 계속 누적되므로 전체 저장 공간이 크게 줄어드는 방식이 아니라 자주 사용하는 펫 파일의 읽기·쓰기 부담을 줄이는 방식이다.

검증은 합성 데이터로 전체 이전, 재실행, 백업 복원 잔류, 중복 개수, 같은 ID의 다른 내용, 저장 단계/완료 표시 실패, 중단 복구, 자동일퀘 묶음 저장 실패, 재컴파일 복구, Info 차단, 파일 누락·손상·충돌, DEV 격리, 일반 명령 미로드를 포함한다. Rhino 1.7.15에서 전체 컴파일과 이전·재이전·특수 이름 처리를 확인한다.
