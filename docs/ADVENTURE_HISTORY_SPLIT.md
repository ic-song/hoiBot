# 모험가 퀘스트 완료 기록·타이틀 분리

`ver_2.648`은 현재 진행·완료 단계·보상 지급 확인·누적 효과를 회원 파일에 유지하고, 전체 완료 기록과 획득 타이틀 배열을 별도 파일로 보관한다. 기록 문장과 시각, 배열 순서와 모든 보상은 그대로 유지한다. 기록 설명을 공통 설정으로 다시 만들거나 삭제하지 않는다.

## 운영 적용

1. 운영자가 새 MAIN/Info 코드를 적용·컴파일한다. 기존 운영 JSON을 수동 교체하지 않는다.
2. 기존 허용 명령어방에서 Admin/Master가 `/데이터정리`를 실행한다. 회원 분리 잔류 로그 복구가 먼저 필요하면 그 복구 완료 후 다시 실행한다.
3. 퀘스트 기록 분리 완료 메시지와 기록/타이틀 건수를 확인한다. 이 실행은 이전 완료 후 반환하므로 다른 일반 정리를 함께 실행하지 않는다.
4. `/퀘스트기록`, `/퀘스트타이틀`, Info `/레벨`, 다음 `/퀘스트완료`를 확인한다. 과거 완료 보상은 재지급하지 않는다.
5. 다른 일반 정리가 필요하면 `/데이터정리`를 다시 실행한다. 이전 완료 표시가 있으면 퀘스트 기록은 다시 옮기지 않는다.

추가 JSON 파일을 최초 업로드할 필요는 없다. 운영 또는 DEV의 활성 데이터 경로에 봇이 아래 파일을 생성한다. 기존의 전체 데이터 백업에 이 파일들도 포함해야 한다.

## 파일과 저장 경계

- `adventureQuestHistory.json`: `{schemaVersion:1,users:{사용자:{records:[],titles:[]}}}`. 사용자 키는 자체 속성으로 생성한다.
- `adventureQuestHistory_legacy.json`: 최초 이전 완료 기록/타이틀 원본 보관. 실패 후 재실행해도 처음 보관본은 덮어쓰지 않는다.
- `adventureQuestHistoryPending.json`: 진행 중인 기록·회원 저장의 복구 원문. 회원 원본/두 백업, 퀘스트 기록, 서버대전·운영 로그의 두 슬롯/두 백업 세트를 함께 보관한다. 임의 경로·중복 이름·손상 원문은 쓰기 전에 거부한다.
- 회원 `migrations.adventureQuestHistorySplit20261014 = true`: 일회성 이전 완료 표시.
- 회원 `adventureQuest.equippedTitleName`: Info 표시를 유지하는 장착 타이틀 이름. 번호·효과·지급 확인·완료 단계는 기존 회원 상태에 유지한다.

분리 후 퀘스트 명령은 기록 파일을 한 번 로드하고 현재 사용자 배열을 비열거 속성으로 연결한다. 일반 행동 기록과 보상 계산에서는 외부 배열을 로드하거나 회원 파일에 다시 만들지 않는다. 새 기록이 없으면 기록 파일을 다시 저장하지 않는다.

기록 변경 시 `saveJsonFile`의 기존 저장 진입에서 복구 원문 → 별도 기록 → 회원/보상 → 복구 완료를 처리한다. 기존 명령 트랜잭션은 오류 시 저장 파일을 복원한다. 프로세스 중단은 다음 MAIN 진입 또는 시작 시 복구 원문 세트를 복원하며, Info는 복구 대기 중 일부 반영된 정보를 표시하지 않는다. 보상·기록 상태가 맞지 않으면 완료 명령을 거부한다. 단독으로 회원의 과거 백업만 복원하여 보상을 다시 지급하지 않는다.

명시적 계정 삭제는 그 계정의 별도 퀘스트 기록도 삭제한다. 닉네임 변경 시 자동 기록 이전 기능은 추가하지 않는다.

## 정리 명령 변경

사용자 요청으로 완료된 옛 아이템 명칭 변경, 펫스킬 이전, 옛 패스 명단 제거, 사용자/길드창고 반지 제거, 잘못 지급된 자동공격권/구형 플래그 제거 코드를 삭제했다. 옛 백업을 복원해도 이 변환들은 다시 실행되지 않는다.

현재 회원·강탈 파일의 분리 검증과 복구는 유지한다. 펫홈의 불필요 데이터, 숫자 0 가방 항목, 포인트 소수점, 잔여 계정 데이터 정리는 계속 제공한다. 가방 정리는 다른 수량이나 구독 상태를 변경하지 않는다.

## 검증

- 합성 계정으로 전체 이전·재실행·정상 완료·중복 지급 방지·조회·장착/해제·첫 참여·8/9단계 연속 완료를 실행한다.
- 이전 및 완료 저장 단계별 실패, 복구 표시 완료 저장 실패, 재시작, 회원과 기록 버전 불일치, 누락/손상/허용하지 않은 복구 경로, DEV 격리를 검증한다.
- Rhino에서 전체 MAIN/Info 컴파일과 실제 이전·비열거 연결을 검증한다.
- 07 백업은 복사본의 순수 이전 계획으로만 대조했다. 완료 기록과 타이틀 각각 2,031건을 보존하며 회원 데이터 1,767,907 → 1,321,490바이트를 확인했다. 원본 운영 스냅샷은 수정하지 않았다.

Git 운영반영은 검증된 소스를 `feature/prod`에 반영하는 단계다. 기기 적용·컴파일 및 실제 운영 확인은 운영자가 수행한다.
