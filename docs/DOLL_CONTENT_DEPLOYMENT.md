# 레거시 인형뽑기 배포 안내

기획: https://app.notion.com/p/2cf393bdd7aa83f4b1a301accd4d28eb

Codex의 운영반영은 원격 `feature/prod` 소스 반영까지다. 아래 파일 업로드와 컴파일은 운영자가 기존 절차로 진행한다.

## 최초 설치

1. 기존 회원·펫·운영 데이터의 백업을 보관한다.
2. 신규 고정 목록 `data/dollCatalog.json`을 `/sdcard/호이랜드/dollCatalog.json`에 배치한다.
3. `data/dollIndex.json`, `data/dollPending.json`, `data/dollRecords_0.json`부터 `data/dollRecords_15.json`까지를 같은 경로에 최초 한 번 배치한다. 이미 존재하는 운영 파일은 빈 초기 파일로 덮어쓰지 않는다.
4. 검증된 같은 버전의 `main.js`와 `Info.js`를 기존 절차로 반영·컴파일한다.
5. DEV에서는 기존 `dev/데이터백업` 절차로 전용 사용자 파일을 복사한다. 고정 목록은 변경하지 않는 공통 파일로 읽는다.

최초 설치에는 고정 목록 1개와 초기 사용자/복구 파일 18개가 필요하다. 일부만 배치하면 누락 오류를 그대로 발생시키며 빈 데이터를 대신 만들지 않는다.

`03_main_운영반영.bat`와 `04_info_운영반영.bat`는 인형 초기 파일 19개를 설치하지 않는다. 코드 업로드와 별도로 위 경로에 배치해야 한다. `07_데이터_백업.bat`는 기기의 실제 파일 목록을 저장소에 그대로 반영하므로, 아직 설치하지 않은 파일은 백업 후 저장소에서도 빠질 수 있다. 백업에서 파일이 없음을 확인한 경우에만 최초 설치용 원본을 사용한다.

## 1,344종 확장 업데이트

기획: https://app.notion.com/p/711393bdd7aa8378957b01fe8efbc5f2

- 운영자가 기존 절차로 요청 처리를 중단하고 미완료 인형 저장의 복구 여부를 확인한 뒤, 기존 카탈로그 D0001~D1000의 ID·이름·등급·크기와 배포본을 대조한다. 기존 ID가 다르면 덮어쓰지 않고 원인을 확인한다.
- 일치하는 기존 1,000종은 유지하고 D1001~D1344가 추가된 `data/dollCatalog.json`과 같은 버전의 `main.js`·`Info.js`를 함께 반영·컴파일한다. 일반 코드 업로드만으로 카탈로그 파일이 갱신되지는 않는다.
- 고정 목록만 갱신할 때는 운영자가 `tools/08_인형목록_운영반영.bat`을 실행한다. 기존 목록의 ID·이름·등급·크기·스페셜 여부를 대조하고 임시 업로드 파일의 SHA-256을 확인한 뒤 목록 한 개만 교체한다. 동일 파일이면 업로드를 생략한다. 누락·잘못된 기존 목록·정의 불일치·전송 실패는 교체하지 않고 종료한다. 작업 중 인형 명령 처리를 중단하고, 완료 후 `03_main_운영반영.bat`으로 main을 반영·컴파일하여 캐시를 갱신한다. Info.js 변경이 아직 반영되지 않았다면 `04_info_운영반영.bat`도 기존 절차로 실행한다. 이 전용 배치는 Git 초기화·개인 데이터 업로드·자동 컴파일을 수행하지 않는다.
- 기존 `dollRecords_0.json`~`dollRecords_15.json`, `dollIndex.json`, `dollPending.json`, 회원·펫 파일을 저장소 스냅샷으로 교체하지 않는다. 수집 기록·최고 크기·횟수·누적 매력은 유지하며 신규 보상을 소급 지급하지 않는다. 기존 JSON 정리는 `/데이터정리`에서만 수행한다.
- 배포한 카탈로그는 첫 인형 이용 때 검증·캐시한다. 사용자 기록을 시작 시 전량 읽거나 자동 마이그레이션하지 않는다. 동일한 카탈로그를 다시 반영해도 종수나 기존 보상이 중복 증가하지 않는다.
- `/인형가이드`, `/인형도감`, 일반·고급·희귀3페이지와 `/인형도감 스페셜`·엘리트, 기존 💠 엘리트 상자 사용을 확인한다. 실기기 allsee·긴 이름·✡️ 표시는 운영자가 별도로 확인한다.

## 기록 보관

- 도감은 이름 기준의 16개 전용 파일에 보관한다. 이름 변경에 따른 기록 이전은 이번 범위에 포함하지 않는다.
- 회원 파일에는 도감 원본을 넣지 않는다. 펫 파일에는 캐슬·레이드 계산에 사용하는 누적 종합매력 요약만 저장한다.
- `dollIndex.json`은 순위용 대표 기록, `dollPending.json`은 완료되지 않은 뽑기의 이전 파일 원문이다.
- 완료되지 않은 뽑기는 다음 MAIN 요청에서 이전 원문으로 복구한다. 복구 기록이 남아 있으면 Info는 부분 반영 상태를 출력하지 않는다.
- 이후 소스 갱신 때 사용자·복구 파일을 초기 파일로 교체하지 않는다. 고정 목록 수정이 필요할 때도 기존 ID를 임의로 바꾸지 않는다.

## 운영 확인

- `/인형가이드`의 비용·확률·매력 설명을 확인한다.
- DEV에서 뽑기·도감·순위와 마지막 이용권 안내를 확인한다.
- 150종 상세 도감의 전체보기와 긴 출력이 카카오톡에서 정상 표시되는지 확인한다.
- 프리미엄 이용권은 기존 구독 보상의 날짜별 중복 방지를 따른다. 이미 오늘의 구독 보상을 받은 계정은 같은 날짜 재실행으로 이용권을 추가 지급받지 않는다.

## 2026-10-14 배포 준비 변경

- 인형 포인트 비용은 10억이며 사용액과 실제 잔액을 별도 줄로 표시한다. 전체알림은 초월·창세·창조만 유지한다.
- ver_2.643부터 인형 관련 명령의 전용 방 제한은 해제한다. 기존 가입·출석·개인톡·대전 제한은 유지하며 일반 패스 관리자 `호이 남`이 `/인형패스추가, 아이디 YY.MM.DD`, `/인형패스추가, 아이디 영구권`, `/인형패스삭제, 아이디`를 사용한다. `/자동출첵`의 유효 패스 지급은 하루 이용권 3개다. 같은 날 연장·삭제 후 재등록해도 추가 지급하지 않는다.
- MASTER의 `/인형전체초기화`는 도감·순위·누적 인형 매력만 지운다. 인형패스·보유 이용권·포인트·경험치·고정 목록은 보존한다. 대전 중에는 초기화하지 않는다.
- ver_2.644부터 인형패스 일일 보상은 기존 이용권 3개와 `인형뽑기확률UP🧸(20%)` 3개다. 오늘 이미 지급받았다면 다음 지급일부터 추가 보상을 받는다. 신규 초기 JSON 파일은 필요하지 않으며 확률UP 5종은 기존 가방에 저장한다. 뽑기 시 50→40→30→20→10% 순서로 한 종류 1개를 사용하고 성공·실패 모두 소모한다. 성공률은 기존 값에 더해 최대 100%로 적용한다.
- 이번 변경은 기존 19개 파일 구조를 사용한다. 설치가 끝난 운영 기록 파일을 초기 템플릿으로 덮어쓰지 않는다. 인형 전용 2초 대기는 스펙아웃이다.
