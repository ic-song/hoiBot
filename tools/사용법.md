# 호이봇 코드 작업 안내

이 문서는 Git 명령어를 직접 입력하지 않고 `tools/` 배치 파일로 코드 작업과 운영 반영을 진행하는 방법을 정리합니다.

---

## 1. 기본 원칙

`tools/`의 배치파일은 번호가 붙어 있어도 서로 자동으로 연결되어 동작하는 흐름을 보장하지 않습니다.
각 배치파일은 필요한 상황에 맞춰 개별 실행하는 도구입니다.
이 문서는 실행 순서가 아니라 각 파일의 역할을 설명합니다.

---

## 2. 운영 반영

`03_main_운영반영.bat`와 `04_info_운영반영.bat`는 최신 `feature/prod`를 받은 뒤 LD플레이어 운영 봇에 파일을 업로드합니다.

두 스크립트 모두 `data/hoiBotChangeLog.json`을 함께 `/storage/emulated/0/호이랜드/hoiBotChangeLog.json`에 업로드합니다.

실행하면 먼저 `LD_CONSOLE_EXE`, `TARGET_LD_INDEX`, 업로드 대상 경로를 보여주고, 단계별 `[STEP]`, `[OK]`, `[FAIL]` 로그를 출력합니다. `ldconsole.exe 파일 없음`이 보이면 배치 파일 상단의 `LD_CONSOLE_EXE` 값을 실제 LDPlayer `ldconsole.exe` 경로로 수정해야 합니다.

`03_main_운영반영.bat`와 `04_info_운영반영.bat`는 기본값 `TARGET_LD_INDEX=auto`로 실행됩니다. `ldconsole.exe list2`의 각 인스턴스를 확인해 배치 파일 상단의 고정 `TARGET_FILE` 경로가 있는 LDPlayer를 하나만 찾으면 자동으로 선택합니다. 후보가 없거나 2개 이상이면 안전을 위해 실패합니다.

`adb connect`로 연결된 device가 정확히 1개 있으면 `03_main_운영반영.bat`와 `04_info_운영반영.bat`는 직접 ADB 방식을 우선 사용합니다. 이때도 봇 파일 경로는 자동 탐색하지 않고 배치 파일 상단의 고정 `TARGET_FILE`을 사용합니다.

자동 감지가 맞지 않으면 배치 파일 상단의 `TARGET_LD_INDEX`를 운영 인스턴스 번호로 직접 지정할 수 있습니다.

---

## 3. LDPlayer 운영 데이터 가져오기

운영 PC의 LDPlayer 안에 있는 실제 운영 데이터를 로컬 저장소의 `data/` 폴더로 최신화할 때 실행합니다.

```text
07_데이터_백업.bat 실행
```

실행 전 MessengerBot의 데이터 쓰기를 멈춘 뒤 확인 질문에 `Y`를 입력합니다. 스크립트는 ADB로 `/storage/emulated/0/호이랜드/` 내부의 모든 파일과 하위 폴더를 임시 staging에 가져와 빈 파일과 JSON의 UTF-8·파싱 상태를 검증한 다음, 실행한 저장소의 `data/`를 운영 폴더와 동일하게 전체 최신화합니다.

검증된 전체 데이터는 임시 Git worktree에서 최신 `origin/feature/prod`를 기준으로 커밋합니다. 같은 커밋을 먼저 `feature/hoi`에 push해 출처를 남긴 뒤 `feature/prod`에 fast-forward push하고 원격 commit을 재검증합니다. 현재 체크아웃을 강제로 초기화하거나 다른 작업 파일을 정리하지 않으며, 실행 전 `data/`에 미정리 변경이 있으면 중단합니다.

운영 폴더 전체를 기준으로 `/MIR` 최신화하므로 운영에 없는 기존 `data/` 파일은 삭제 대상으로 처리됩니다. 실행 전 대상 LDPlayer와 MessengerBot 데이터 쓰기 중지 여부를 반드시 확인해야 합니다.

## 4. 펫홈 댓글 파일 생성

운영 봇에서 펫홈 댓글 파일이 없을 때 Admin/Master 계정으로 실행합니다.

```text
/펫홈댓글파일생성
```

이 명령어는 `/sdcard/호이랜드/petHomeComments.json` 존재 여부를 확인하고, 없을 때만 초기 구조 `{ "comments": {} }`로 생성합니다. 이미 파일이 있으면 댓글 데이터 보호를 위해 덮어쓰지 않습니다.

파일 생성 후 `/데이터정리`를 실행하면 기존 `petSweetHomeData.json` 안의 `guestComments`는 새 댓글 파일로 옮기지 않고 홈 데이터에서 제거합니다.

## 5. Codex Skills 설치/업데이트

작업 환경이 바뀌었거나 새 PC/새 Codex 환경에서 작업할 때 실행합니다.
로컬 junction은 어느 브랜치에서도 갱신하지만, 프로젝트 skill 미러는 `feature/workflow`에서만 갱신합니다.

```text
05_skills_설치.bat 실행
```

중앙화 대상:

```text
중앙 원본:    %USERPROFILE%\CODEX-CONFIG\skills\
프로젝트 미러: .codex/skills/
로컬 사용:    %USERPROFILE%\.codex\skills\ → 중앙 원본 junction
한국어 검토본: .codex/skill-drafts-ko/
```

| `01_새작업시작.bat` | 원격 `origin/feature/prod`를 확인한 뒤, 원격 최신 운영 기준으로 `feature/hoi`를 초기화합니다. |

| `07_데이터_백업.bat` | ADB로 LDPlayer의 `/storage/emulated/0/호이랜드/` 전체를 로컬 `data/`와 미러링하고, 검증된 동일 커밋을 `feature/hoi`에 먼저 push한 뒤 `feature/prod`에 반영합니다. |
