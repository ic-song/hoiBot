# 호월주사위 연타의 응답 잠금 대기 누적 방지

- 기준: `67fe0b98473e24463cc801203a3509da494bd77e` / ver_2.719 → ver_2.720, 2026-10-27 KST.
- 운영 보고: `ㅎㅈ` 연속 입력 중 봇이 멈춘다는 제보. 운영 기기에는 접속하지 않았다. 실제 기기 정지의 모든 원인을 단정하지 않고 개발 PC에서 확인한 잠금 대기 누적 경로를 수정했다.
- 기존 `response`는 `ㅎㅈ`·정식 명령·DEV 단축키 모두 배타 데이터 흐름 잠금의 `lock()`을 무기한 기다렸다. 앞선 처리나 조회가 잠금을 보유하면 연타 콜백이 대기열에 쌓이고, 뒤따른 일반 응답도 지연될 수 있었다.

## 변경과 보존 경계

- 정확한 `/호월주사위`, 기존 규칙대로 앞뒤 공백을 제거한 `ㅎㅈ`, 같은 명령으로 정규화되는 DEV 입력만 `tryLock(0, TimeUnit.MILLISECONDS)`로 흐름 잠금을 시도한다. 공정 잠금의 대기 순서를 따르며 주사위 요청을 새 대기열에 쌓지 않는다.
- 잠금이 바쁘면 파일 읽기·트랜잭션·횟수 소모·응답 전송 전에 반환한다. 연타에 대한 안내 메시지를 계속 보내 추가 부하를 만들지 않는다. 첫 화면을 받은 뒤 다음 입력을 하면 기존 두 번째 굴림이 진행된다. 고정 쿨다운은 추가하지 않았다.
- 잠금 시도가 중단되면 스레드의 중단 표시를 복원하고 반환한다. 다른 잠금 오류는 숨기지 않는다. 획득한 잠금은 기존 `finally`에서만 해제하고, 획득하지 않은 잠금은 해제하지 않는다.
- 다른 명령·잘못된 단축키의 잠금 방식, 등록/출석/권한 검사, 주사위 두 화면·4판 제한·확률·보상·연승·공지·저널·중단 복구·DEV/PROD 경로는 유지한다.
- 공용 Node 저장 하네스에는 실제 Java API의 `TimeUnit.MILLISECONDS` 상수만 추가했다. 런타임 대체 경로나 가짜 API 폴백은 추가하지 않았다.
- 기존 `feature/bugFix`의 미반영 작업은 보존하고 최신 운영 소스에서 별도 `feature/dice-burst-fix`로 작업했다.
