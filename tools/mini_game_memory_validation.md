# 미니게임 저장 중복 생성 감소

- 기준: `origin/feature/prod` ver_2.705 → ver_2.706, 2026-10-26 KST.
- 사용자 요청: 기존 기능을 유지한 최적화. 후속 지시에 따라 전후 성능·힙 사용량 비교는 실시하지 않았다.
- 기존 작업본의 되돌림/삭제 변경은 보존했다. `feature/prod`에서 만든 별도 `feature/mini-game-memory` 작업 트리에서 수정했다. 이전 일일 리셋 통일 작업의 미반영 커밋은 포함하지 않는다.

## 변경 범위

- 보관 파일을 읽을 때 전체 문자열로 다시 직렬화해 보관하던 비교 원문을 제거했다. 실제 기록을 추가한 곳에서 변경을 표시하고, 변경된 월별 파일만 저장 직전에 한 번 직렬화한다. 조회 경로는 변경 표시를 하지 않는다.
- 일일 리셋 계획에서 사용하지 않던 진행 비교 문자열 생성을 생략했다. 일반 저장에서는 변경 판정을 마친 이전 진행 비교 문자열을 복구 원문 생성 전에 해제한다. 이후 저장 오류는 기존 진입부 예외 흐름을 따라 종료·복구한다.
- 금고 시작 함수가 `store.current`를 새 객체로 교체하는 기존 동작을 확인하고, 종료/관리자 리셋 회차의 불필요한 전체 JSON 복제를 제거했다. 보관한 이전 회차의 횟수와 다음 명령의 활성 회차 기록이 서로 영향을 주지 않는지 확인했다.

보상·확률·횟수·명령 가드·UI·공지 상태·타이머 정책과 일일 리셋 기준은 변경하지 않았다. `miniGamePending.json` 버전1의 문자열 원문 형식, 원문 검증, 회원/보관/진행 게시 순서, 저널 정리 경계와 DEV/운영 경로는 유지한다. 파일 누락·파싱 오류를 기본값으로 바꾸지 않는다.
