## 기능과 명령

- 기존 MASTER와 허용 방 판정을 재사용한다. `/교육` 안내, `/교육 1`~`10` 매뉴얼, `/교육 닉네임` 진행도, `/교육완료 닉네임 챕터번호`, `/교육실적`, `/교육실적 GM닉네임`, `/교육실적 전체`.
- 공백 닉네임 전체와 마지막 챕터 정수 1~10을 분리한다. 추가 문구·소수·음수·범위 초과는 지급하지 않는다. 숫자 닉네임은 `/교육 @1`처럼 명시하거나 기존 내부 계정 ID를 사용한다. `@`는 명시적 닉네임 조회 접두사이며 실제 @로 시작하는 닉네임은 @@로 조회할 수 있다.
- 1→10 순차·계정당 1회, 챕터마다 실제 가방 아이템 `다이아상자💎(소)` 1개. 총 10개이며 수료 추가 보상은 없다. 실제 완료한 GM에게 해당 챕터만 기록한다. 담당 GM 교대나 닉변은 이전 완료·보상을 초기화하지 않는다.
- 공통 매뉴얼 10개는 서버·권한·장비·재화 조건을 바꾸지 않는다. 보유 장비나 진행 대전이 없어도 설명·조회·예시로 교육할 수 있다. 강화·구매·가입·거래·유료 이용은 교육 조건이 아니다. 자동 완료·자동 시험·별도 출석·타이머·초기화 명령 없음.
- 실적은 확정 챕터만 계산한다. GM별 챕터 수·교육 인원, 전체 중복 제외 인원·진행 중·수료·완료 수, 공동 순위와 닉네임 정렬. 빈 실적은 빈 전체보기 없이 안내한다.
- `/내정보` 레벨 다음 한 줄에 0/10·부분 완료·수료 표시. 기존 항목은 유지한다. 캐시는 환경별 교육 파일 수정 시각/크기로 갱신하며, 반복 조회로 교육 JSON 읽기·저장을 반복하지 않는다.

## 저장·실패·중단

- 원본 `gmEducation.json`은 계정 ID별 최대 10개 챕터·담당 GM·시각·처리 키만 보관한다. 매뉴얼은 공통 설정, 실적은 원본에서 계산하므로 복제 파일이 없다.
- 기존 `serverRaidAccount.id`를 안정 키로 재사용한다. 없는 대상/GM은 ID만 먼저 회원 저장으로 확정한다. 회원 전체를 다른 파일로 옮기지 않는다.
- 영속 `gmEducationPending.json` → 기존 회원 가방+최대 10개 지급 영수증 동시 저장 → 교육 완료 저장 → pending 삭제 → 성공 출력. 각 저장을 별도 확정하므로 지급 뒤 교육 저장 실패·응답 실패가 지급을 취소하지 않는다.
- 다음 Main 응답 전처리에서 pending을 복구한다. 지급 영수증이 있으면 아이템을 다시 주지 않고 교육 기록만 확정하며, 없으면 기존 GM/처리 키로 미지급과 기록을 처리한다. 복구 실패 중에는 새 완료를 실행하지 않는다. 현재 계정 ID가 없거나 기록/영수증이 충돌하면 실패를 유지한다.
- `.rollback` 게시 중단 파일은 기존 방식으로 검증 후 복구한다. 기존 파일의 손상·잘못된 형식·누락된 완료 원본과 지급 영수증 충돌은 빈 저장소로 덮지 않는다. 최초 전용 파일 미생성만 신규 미진행으로 취급한다.
- PROD `/sdcard/호이랜드/`, DEV `/sdcard/호이랜드_dev/`로 회원·교육·pending을 분리한다. 교육 조회는 저장하지 않으며 분리 회원 레이드/운영 로그 슬롯도 바꾸지 않는다.
- pending과 지급 영수증은 중복 지급 판정에 필요하므로 임의로 지우거나 초기화하지 않는다. 오처리 정정은 기존 운영 절차에서 실제 지급/완료/실적을 함께 대조한다.

## 기존 명령 대조

- Main/Info 실제 분기와 대조: 내정보·펫정보·가방·레벨순위, 모험가퀘스트/퀘스트기록/퀘스트완료, 펫스킬/가방/정보/장착, 미니펫정보/가방/대표·보조 장착/강화, 펜던트가방/정보/장착/강화/복원, 펫홈/가구정보, 길드목록/정보/가입, 서버대전/캐슬대전/미니펫대전, 인형가이드, 당근 거래 5종.
- 미니펫 강화의 `0`은 대표, `00`은 보조, 양수는 가방 번호. 현재 펜던트 표기는 `펜던트`이며 `0`은 장착 대상이다. 빌리지·별채는 현재 소스에 있으며 조건은 게임 안내에 연결한다. 거래 최종 응답은 `거래한다`/`안한다`를 사용한다. 종료된 정령·강화뽑기를 매뉴얼에 넣지 않는다.

운영자가 `main.js`, `Info.js`, 개발자노트 데이터를 적용·컴파일한 뒤 허용된 운영방에서 MASTER로 `/교육`과 `/교육 1`을 확인한다. 실제 챕터 완료는 GM의 설명·실습 확인 후 `/교육완료 닉네임 숫자`로 처리한다. 교육 전용 JSON은 첫 정상 완료 시 생성되며 빈 파일을 수동 업로드할 필요가 없다. Android/Kakao 전체보기 렌더링과 실제 운영 계정 동작은 운영자 확인 영역이다.
