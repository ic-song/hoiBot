## 변경과 보존 범위

런타임 변경은 `main.js`의 `getPetHomeBadgeById` 하나와 버전뿐이다. 활성 명령의 기존 Java ThreadLocal 컨텍스트에 고정 정의의 임시 조회 인덱스를 둔다. 첫 문자열 ID 조회는 기존 선형 검색을 수행하며 해당 결과만 기록한다. 추가 조회는 필요할 때까지만 원래 순서로 탐색하면서 첫 일치 정의를 색인한다. 최대 204개 정의만 보관하며 임의의 없는 ID·회원 데이터·보유/삭제/장착 상태는 보관하지 않는다. 명령 종료 시 컨텍스트와 함께 해제되고 DEV/PROD·중첩·동시 실행 사이에는 공유하지 않는다.

현재 코드는 명령 안에서 고정 뱃지 설정 배열이나 ID를 변경하지 않는다. 설정 편집·목록 추가·동일 배열 원소 교체는 다음 명령에 즉시 반영되는지 검증했다. 원본 정의 객체를 반환하므로 효과 등 속성은 복사하거나 변환하지 않는다. 새로운 명령 내부의 동적 설정 변경 기능을 추후 추가할 경우 조회 인덱스의 무효화도 함께 검토해야 한다.

`getAllPetHomeBadges`는 계속 새 배열을 원래 순서로 반환한다. 목록·가방 번호·숫자 선택·장착·해제·영구 삭제·재획득 차단·큐브·확률·보상·동점 순서·UI·allsee·저장·롤백·JSON 오류·7인수 response 계약은 변경하지 않는다. 비문자 ID는 기존 엄격 비교 검색을 그대로 사용하고, 활성 컨텍스트가 없는 독립 호출도 기존 검색을 수행한다. 보류한 7번 가방 개선과 `Info.js`는 수정하지 않았다.

## 개선 전후 비교

동일 JVM의 독립 전후 스코프를 번갈아 실행했다. 워밍업 5회 후 20회 중앙값이며 입력 준비는 측정에서 제외했다. 원래 조회 및 순위 함수를 계측 없이 시간 측정하고 횟수는 별도로 계측했다. 회원명/헤더 등 변경하지 않은 표시 제공자는 고정했다. 전체 콜백·파일 로드 시간이나 Android 운영 시간은 측정하지 않았다. 원본 시간 샘플은 `home_badge_lookup_benchmark.json`에 기록했다.

| 구간 | 기존 중앙값(ms) | 변경 중앙값(ms) |
| --- | ---: | ---: |
| 한 명령에서 ID 100회 조회 | 86.2295 | 8.5080 |
| 한 명령에서 ID 5,000회 조회 | 255.0593 | 17.0506 |
| 1회 조회 명령 100개 | 10.4651 | 14.3558 |
| 실제 뱃지 순위 생성 / 100명 | 116.4504 | 13.7615 |
| 실제 뱃지 순위 생성 / 1,000명 | 1,258.5293 | 134.1344 |

1,000명 × 22개 보유 ID(중복/없는 ID 포함) 기준으로 정의 배열 합치기는 **22,000→1회**, 정의 ID 읽기는 **3,973,500→408회**로 감소했다. 순위 생성 구간은 이 합성 조건에서 약 89% 단축됐다. 단건 명령은 100개 합계 약 3.89ms, 한 개당 환산 약 0.039ms 증가했다. 단건 조회 비용을 줄이기 위해 첫 조회의 전체 인덱스 구축을 지연했으나 임시 컨텍스트 조회·메타데이터 준비 비용은 남는다. 반복 조회 개선을 전체 명령/모든 입력의 속도 개선으로 확대 해석하지 않는다.

## 운영 반영

개발자노트와 `HoiBotVersion`을 함께 `2.696`으로 갱신했다. 기획 DB에서 홈뱃지 관련 기존 7개 문서는 모두 LIVE이며, 이번 정의 조회 성능 개선에 해당하는 별도 READY/HOTFIX 문서는 확인되지 않았다. 기존 LIVE 속성과 본문은 유지하고 새 Notion 페이지를 만들지 않는다. 스킬 변경도 없다.

운영 반영은 검증된 작업 브랜치 push → `feature/prod` 반영/push → `origin/feature/prod` 검증 범위다. 운영 기기 업로드·컴파일은 운영자가 진행한다.
