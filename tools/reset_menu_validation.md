# 수동 초기화 통합 메뉴 검증

- 기준: origin/feature/prod e024cffcaf88c54e89003254253685613fd6846e / ver_2.672, feature/home-content-reset.
- 운영반영 전 구현·검증 결과다. 버전·개발자노트·Notion·카카오 알림·운영 데이터는 변경하지 않는다. 실제 앱 업로드·컴파일·초기화 실행은 하지 않았다.

## 동작과 범위

- `/초기화` → 권한별 번호 선택 → 대상·범위 확인 → 정확히 `1삭제` 또는 `2취소`. 대상형은 `번호 아이디`, `번호 아이디 횟수`, `번호 서버`로 입력한다.
- 기존 수동 명령은 메뉴 안내로 바꾸고 실제 본문은 확인을 소비한 응답에서 재사용한다. 아래 30항목에 대해 직접 명령/접미사 우회 차단을 검증했다.
- 사용자·환경·방·그룹에 묶인 메모리 세션, 단계별 60초 만료, 재컴파일 취소, 권한/패스/길드 변경 취소, 확인 1회 소비, DEV/PROD 분리.
- 메뉴·미리보기는 저장하지 않는다. 새 댓글·피드는 진입부에서 최신 두 파일을 읽고 순수 계획을 적용해 변경 파일만 저장한다. 저장 예외는 기존 명령 트랜잭션·작업 전 스냅샷으로 원복한다.
- 일반·픽 댓글/댓글 알림 또는 피드·이전 한줄평/피드 알림만 제거한다. 기존 guestComments·재화·가구·방문·누적 소셜 통계는 보존한다.
- 마스터 명단 초기화는 기존 분기의 별도 권한 검사 부재를 그대로 노출하지 않고 통합 메뉴에서 MASTER 전용으로 제한했다. 그 외 기존 역할·방·자원 조건과 최종 처리 본문은 유지한다.

## 적용 조건과 한계

- Main과 Info를 함께 적용한다. 실제 Android MessengerBot 기기에서는 실행하지 않았다.
- 앱 강제 종료 시 여러 파일의 원자성은 기존 트랜잭션과 동일하다. 확인 대기는 복구되지 않으며 새 메뉴 확인으로 남은 기록/알림만 정리할 수 있다.
- 정기 `/리셋`, `/주기리셋`, notice.js 알림 운영 명령과 별도 데이터/가방 정리·일회성 이전은 이 메뉴로 바꾸지 않았다.
