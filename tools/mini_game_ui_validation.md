# 미니게임 2메시지 UI·단축키·금고 특별 힌트 제거

- 작업 기준: `origin/feature/prod` ver_2.702 → ver_2.703, 2026-10-26 KST.
- 기획: [주사위 UI 2칸](https://app.notion.com/p/266393bdd7aa8399b303814e795277fb), [금고 난이도·단축키](https://app.notion.com/p/2a5393bdd7aa8354ae38012b77dd71b0). 두 페이지의 `상태 = 🛠 READY`를 DB 속성으로 확인했다.
- 사용자의 최종 지시: `자정기준 = /리셋 명령어시`. 금고·밸런스·주사위의 일일 회차는 시계 자정이 아닌 실제 `/리셋` 실행 시 전환한다. 자정에 `/리셋`을 실행하는 운영 절차는 Codex에서 새로 예약하거나 변경하지 않았다. 기획서의 정오 표현보다 이 최종 지시를 우선하며 기획 본문은 수정하지 않는다.
- 정상 운영 데이터와 Android 기기를 변경하지 않았다. 시험은 메모리 합성 자료 및 OS 임시 폴더의 Java 파일만 사용한다.

## 적용 내용

- `ㅎㅈ`는 앞뒤 공백을 제거한 정확한 문자열일 때만 `/호월주사위`로 처리한다. DEV와 배타 잠금도 같은 경로를 사용한다. 일반 문장·붙임말·슬래시를 붙인 `/ㅎㅈ`는 새 실행 명령으로 허용하지 않는다.
- 첫 입력에서 유저/호월이의 첫 숫자를 확정·저장하고 첫 메시지 하나를 출력한다. 두 번째 입력에서 나머지 숫자·결과·보상을 확정하고 최종 메시지 하나를 출력한다. 별도 자동 숫자 메시지와 정상 보상 완료 메시지는 없다.
- 첫 화면은 프리미엄·목록·첫 숫자·멘트1줄·다음 입력·allsee 규칙을 표시한다. 최종 화면은 양쪽 두 숫자·합계·승부·보상·잔여 판 수만 표시한다. 지급 실패는 `지급 대기`로 표시한다.
- 새 판은 프리미엄 전용 2판 한도다. 이미 시작한 판은 회원권 만료·날짜 변경 후에도 마무리할 수 있다. 두 번째 입력에는 이용 횟수를 추가 차감하지 않는다.
- 구버전 `USER1`/`WAIT_USER2`/`USER2`/`RESULT`의 저장 숫자·멘트·횟수·지급 기록을 보존한다. 저장 단계 번호는 첫 통합 화면1→2, 최종 화면4→5로 이어간다. 미완료 숫자만 채우며 기지급은 다시 지급하지 않는다.
- 금고는 새 특별 힌트를 생성하지 않고 제목·범위 힌트·가이드 문구를 제거한다. 기존 `low`/`high`는 유효성을 확인해 보존한다. 현재 정답과 일일 사용 횟수·최근 UP/DOWN3건·기지급 기록·상한1,000억은 유지한다.
- 일일 `/리셋`은 현재 밸런스를 마감해 미수령 원장을 적립하고 새 질문을 준비한다. 현재 금고가 미당첨이면 리셋 회차당 +5억, 당첨 완료면 기본5억의1차를 준비한다. 개인 금고·새 주사위 판 횟수를 초기화하며 진행 중 주사위와 기존 보상은 유지한다. 자동 작업은 시각만으로 마감·초기화하지 않는다.
- 같은 날짜에 다시 실행한 `/리셋`도 기존 출석과 같이 새 회차다. 날짜·회차 번호로 밸런스 원장·공지·보관/통계를 구분하므로 지난 회차의 지급 증거를 덮어쓰지 않는다. 기존 판은 최초 패치 시 초기화하지 않으며 처음 `/리셋`을 기다린다.
- 기존 `/리셋` 권한은 유지한다. 리셋 계획은 회원·펫 저장 뒤 게시하며 원문/신규 파일을 기존 저장 트랜잭션에 등록한다. 저장 실패는 보관·진행·회원·펫을 복구하고 재시도한다. 불확실한 지급 확인 대기는 미니게임 초기화만 보류하며 일반 일일 리셋은 계속한다. 리셋 명령은 잠금 경합 시 기다린다.

새 시험은 실제7인수 콜백과 DEV 별칭, 정상2메시지, 승/무/패의 정확한 금액, 6개 눈, 구 진행8단계, 기지급 결과, 응답 실패, 지급 대기, 세 게시 중단 경계, 임시 저장/재시작, 자격과 일일 한도, 금고 전체1,000개 숫자를 포함한다. 리셋 시험은 시각만 경과 시 유지·동일 날짜 여러 회차·이전 회차 대기 입력·권한/접미·저장 실패/재시도·기존 판 보존·지급 확인 대기·DEV·시각 역행을 다룬다. 기존 시험의 5메시지·만료 시 중지·폭600 힌트·시계 자정 기대값을 새 요구에 맞춰 변경했다. 다른 기능의 검사를 완화하지 않았다.

Rhino1.7.15에서 실제 Java 스레드의 정규 명령/단축키 동시 입력, 파일 저장·재시작, 두 메시지, 회원권 만료, 지급 대기 복구, 리셋 계획의 보관/진행 롤백, 동일 날짜 회차별 보상 지급을 확인했다. 증거 폴더는 테스트가 출력하는 `hoibot-minigames-rhino-*` 임시 폴더다.

Android 실기 화면·실제 카카오톡 전송 및 운영 업로드·컴파일은 검증하지 않았다. 운영 소스 반영은 검증한 소스 브랜치 푸시 → `feature/prod` 반영/푸시 → 원격 SHA·버전 확인을 뜻한다.
