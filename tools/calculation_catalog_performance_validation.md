11. 이미 첫 이용 때 검증해 보관하는 활성 인형 카탈로그만 등급별로 묶는다. 기존 배열 순서를 유지하며 호출자에게 매번 복사한 배열을 반환한다. 카탈로그 교체는 객체 식별로 무효화하고, 임의 카탈로그와 다른 등급 타입은 원래 엄격 비교 필터를 실행한다. 초기 캐시는 지역 배열을 완성한 후 게시하고, 각 호출은 지역 참조를 사용한다.

확률·난수 호출 순서·보상·차감·게임 기록·저장/복구·DEV/PROD 경로·명령 guard·문구·allsee·7인수 response 계약은 변경하지 않는다. 인형 1,000종 원본, 정적 미니게임 번들, 운영 스냅샷과 스킬 파일은 수정하지 않았다. COMMAND_REGISTRY는 명령 변화가 없어 갱신하지 않는다.

## 운영 소스 반영

기획 DB에서 성능/최적화/반복/계산에 대응하는 별도 항목을 찾지 못했다. 기존 인형·펫정보 기능 문서와 별도의 인형 추가 READY 항목은 이번 내부 성능 작업의 완료 대상으로 변경하지 않는다. 새 노션 페이지나 본문 기록을 만들지 않는다.

반영 범위는 소스 브랜치 push → feature/prod 반영/push → origin/feature/prod의 커밋·버전·개발자노트 확인이다. 운영 기기 접속·업로드·컴파일·재시작은 수행하지 않는다. 운영자는 main.js와 Info.js 및 개발자노트를 함께 업로드하고 컴파일해야 한다.
