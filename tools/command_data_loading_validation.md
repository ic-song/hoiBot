# 명령별 파일 로드 개선 검증

- 버전: `ver_2.691`, 2026-10-25.
- 비교 기준: `48826682e165787c2c1d36b962c2685902c049ef` (`ver_2.690`).
- 레거시 7인수 callback과 명령 목록·입력 가드·권한·메시지·아이템/매력/보상 규칙은 그대로 유지했다.

## 범위

Info 공통의 펫·스킬·회원 타이틀·펫 타이틀 4파일 로드를 실제 소비하는 명령 분기로 옮겼다. 회원·길드를 읽고 검사하는 공통 제한 구간은 이전 소스와 문자열 단위로 동일하다. 포인트·레벨 등은 이 4파일을 읽지 않으며 타이틀 목록은 해당 타이틀, 펫 상태는 펫만 읽는다. 정보·순위 등은 실제 출력과 계산에 필요한 조합을 읽는다. 별도 캐시·지연 로더·가짜 빈 데이터는 추가하지 않았다.

Main은 다이아 누적 기록을 쓰는 11개 분기에서만 `currencyLogPath`를 읽는다. 해당 명령은 종전 공통 위치에서 읽어 읽기 실패와 후속 저장의 순서를 보존한다. 11개 소비 분기의 코드는 이전 소스와 동일하며 지급/차감·소모·계정 삭제·정리의 저장 순서도 유지한다. 다른 Main 공통 파일은 패스 만료·자동 처리·스킬 보정·대전 등에 실제로 필요하므로 유지했다.

기존 로더·저장·잠금·복구 구현은 바꾸지 않았다. 비사용 파일 누락·손상은 해당 명령에서 읽지 않게 되는 것이 의도한 차이다. 필요한 파일은 기존 로더의 오류/복구 정책으로 처리한다. Info의 기존 `|| {}` 등 누락 처리도 새로 확대하지 않았다.

## 검증

- `node tools/test_command_data_loading.js`: **52그룹**. 실제 Info 전체 응답에서 43개 입력의 메시지/저장 동등·각 필요 파일 1회, 같은 43입력의 DEV/운영 격리, 권한/출석/레이드/영지/무쌍/맞짱/정지/약관/개인톡 차단, 3종 복구 대기, 선택 파일 누락·손상, 연속 조회 최신값과 응답 실패 후 컨텍스트 해제를 검증했다.
- Main 11개 소비 분기가 원본과 동일함을 검사하고 13개 유효 입력의 재화 로그 읽기 1회, 일반 조회·일반 대화·접미 안내 입력의 읽기 0회를 확인했다. 실제 지급·차감·상점·순위·초기화 분기와 기존 저장 함수를 실행해 이전 결과 동등·회원/재화 각 저장 지점 실패의 원본 복구·재로드 재시도·DEV 저장 격리도 확인했다.
- `node tools/test_command_data_loading_rhino.js <Rhino 1.7.15 jar> <result.json>`: Main/Info 전체 컴파일, 실제 Rhino+Java UTF-8 파일에서 Info 43입력 및 DEV 43입력의 결과 동등/필요 파일 로드, Main 실제 로더의 비사용 누락·손상 무읽기/필요 손상 JSON 오류/잠금 해제, 전후 읽기 바이트·시간 측정 통과.
- 회귀: 회원 표시/검색 인증 **29**, 회원 분리 **55**, 초기화 정리 **17**, 펫스킬 공통 보정 **10**, 서버 레이드 **130**, 직전 READY **17**, 레이드 펫스킬 **15**그룹 통과. 신규와 합계 **325개 Node 그룹**이다.
- 별도 Info 영지 제한·미니펫 보조 매력/실제 펫정보·모험가 튜토리얼/상점·스타터 중복 조회 테스트도 통과했다. 일부 축약 fixture에는 분기 내 새 로드 경로와 기존 가구 매력 의존성만 보완했다.
- 원본 운영 스냅샷을 사용하거나 수정하지 않았다. Node 문법, UTF-8, 변경 범위, 버전/노트 +0.001 동기화도 확인한다.

## 전후 비교

로컬 Rhino 1.7.15 인터프리터+실제 Java 파일 읽기, 동일 합성 데이터. 회원 1.4MB, 펫 0.9MB, 스킬 0.13MB, 두 타이틀 각 0.5MB의 합성 padding을 사용했다. 파일 이름·개인정보 등 운영 데이터를 사용하지 않았다. 5회 워밍업 후 31회 중앙값이며 이전/이후 순서를 교대로 측정했다.

| 측정 구간 | 입력 | 읽기 횟수 | 읽은 바이트 | 이전 중앙값 | 이후 중앙값 |
|---|---|---:|---:|---:|---:|
| Info 전체 콜백 | /포인트 | 7 → 3 | 3,439,867 → 1,405,222 | 17.597 ms | 7.415 ms |
| Info 전체 콜백 | /레벨 | 6 → 2 | 3,439,854 → 1,405,209 | 22.458 ms | 9.394 ms |
| Info 전체 콜백 | /타이틀목록 | 6 → 3 | 3,439,854 → 1,906,758 | 9.239 ms | 5.040 ms |
| Info 전체 콜백 | /펫정보 | 10 → 9 | 3,441,089 → 2,939,540 | 11.841 ms | 10.541 ms |
| Info 전체 콜백 | /종합순위 | 7 → 5 | 3,441,006 → 2,437,992 | 12.330 ms | 8.920 ms |

| Main 재화 로드 구간 | /다이아순위 | 1 → 1 | 500,050 → 500,050 | 2.156 ms | 1.881 ms |

Info 측정은 전체 callback을 실행하되 메시지 외부 전송은 배열로 기록한다. Main은 실제 로더/파서/Java 잠금을 쓰는 재화 로드 구간만 측정했다. 두 수치를 더해 전체 봇 응답시간으로 해석하면 안 된다. 파일 시스템 캐시·GC·PC 부하에 따라 시간은 변하며 확정적 개선은 불필요한 읽기 횟수와 바이트 감소다. 원 수치는 `command_data_loading_benchmark.json`에 보관한다. 운영 Android 기기 실측은 수행하지 않았다.

운영 반영은 검증된 작업 브랜치 푸시 → feature/prod 반영/푸시 → 원격 소스와 버전·노트 확인 범위다. 운영자는 **main.js와 Info.js를 함께** 업로드·컴파일하고 개발자노트 데이터도 적용해야 한다.
