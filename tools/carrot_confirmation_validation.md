## 개발·저장·예외 검증

- 일반·미니펫·가구·스킬·펜던트 5종 모두 최초 요청 무저장, 동일 비용 확인/차감/완료, 기존 단건/다건 지원·당근온도기/통계 차이를 보존했다.
- 확인 응답을 원래 명령으로 연결하여 공통 출석·정지·대전·장소 검사 경로를 유지한다. 명령 연결 및 실패 시 대기 해제는 13번 시험에서 검증했다. 전체 Android 콜백 자체를 실행한 시험은 아니다.
- 기존 약관 범위, 킹 이상 조건, 수신 공간·슬롯가방 상한, 폐지 스킬과 거래 불가 목록을 유지한다. 수신 재화·통계의 손상과 안전정수 초과도 차단한다.
- 초기 대상 전체 내용과 기존 ID(있는 경우), 최초 가방 번호·정렬 순서를 보존한다. 번호만 바뀌면 같은 대상을 찾고, 동일 개체를 구분할 수 없으면 무차감 취소한다.
- 모든 저장 지점에 실패를 주입하여 원문 복구와 완료 안내 차단, 새 요청 재시도를 확인했다. 완료 안내/부수 로그 전송 실패는 이미 저장된 이전을 되돌리지 않는다.
- DEV/PROD 대기와 데이터 분리, 특수 계정명, JSON 손상/누락, 재컴파일을 가정한 대기 초기화, 잘못된 입력·연속 응답, 정확한 60초 경계와 과거 거래의 만료 콜백을 확인했다.

## 실행 결과와 범위

- 전체 JavaScript 회귀 68회 모두 통과(출석 인수 1~5 및 Rhino 시험 포함). 마지막 기획 대조에서 동명·상이한 강화 물품의 확인/실제 이전 시험을 추가하여 새 기능 16그룹을 재실행했고 모두 통과했다.
- `tools/test_carrot_confirmation_rhino.js`: Rhino 1.7.15에서 MAIN/Info 전체 컴파일, 실제 도메인·명령 흐름 실행, 실제 응답 잠금과 Java 스레드 20쌍의 동시 확정 단일 지급. 파일 시스템과 일부 공통 API는 합성 대체다.
- `tools/test_carrot_community_trade.js`: 기존 4종의 정확한 커뮤니티 단체방 제한과 펜던트의 기존 장소 규칙 구분.
- 추적된 데이터 1,143개 파일은 테스트 전후 해시가 같고 JSON 파싱 오류가 없다. 의도한 데이터 변경은 개발자노트뿐이다.
- 별도 반영/데이터 업로드 워크플로 시험 `test_uploaded_main_version.js`와 PowerShell 시험은 이번 게임 기능 검증에서 제외했다.
- 실제 Android MessengerBot 실행·업로드·컴파일·재시작은 수행하지 않았다.
- 확인 대기는 메모리에만 있으며 재컴파일 후 거래를 재실행하지 않는다. 같은 명령의 저장 예외는 기존 트랜잭션으로 복구한다. 강제 프로세스 종료의 파일 간 영속 원자성까지 보장하는 새 저널은 추가하지 않았다.
