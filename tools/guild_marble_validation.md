## 하루 7회 확대 — ver_2.701

- 사용자 요청으로 길드별 KST 하루 한도만 5→7회로 변경했다. 개인 별도 횟수, 참가·참가비·보상·환급·경기 진행·저장/복구 정책과 보류 중인 이용권은 그대로다.
- 기존 사용 기록을 초기화하지 않는다. 이미 5회를 이용한 길드는 6·7번째 경기를 시작할 수 있고, 8번째 모집은 무저장·무차감으로 거절한다. 가이드 3줄과 명령 색인도 7회로 맞췄다.
- `test_guild_marble.js` 29, `test_guild_marble_improvements.js` 14, `test_guild_marble_settlement.js` 5개 그룹 통과. 기존 5회 저장본의 추가 2회, 상한 거절, 다음 KST 날짜, 취소·참가 실패 무차감, 진행 경기 자정 보존을 확인했다.
- `test_guild_marble_rhino.js`의 전체 Main/Info 컴파일과 실제 Java 파일·동시 스레드·복구·재지급 방지·DEV 격리 등 13개 출력 검증 통과. 다섯 번 이용 후 새 전역 스코프로 재시작해 6·7회 허용/8회 무차감/다음 날짜 초기화를 확인했다.
- 원본 운영 스냅샷은 수정하지 않고 합성 데이터만 사용했다. 명령·도우미·저장 흐름은 변경하지 않았으며 COMMAND_REGISTRY는 그대로다. 운영 기기 업로드·컴파일은 운영자가 수행한다.

## UI·단축키 개선 — ver_2.687

- 기획: [길드마블_UI_단축키_개선기획안](https://app.notion.com/774393bdd7aa83a7b72b01b65657b788). 데이터소스의 상태 🛠 READY와 예정일 `26.10.23` 확인. 기준은 최신 feature/prod `fe9542246f95b245c4a12f7ab0a13cf3805edb6f` / ver_2.686이다.
- 최신 사용자 확정으로 기획의 하루 3회는 **5회**로 변경하고 이용권은 전체 보류했다. 아이템 추가·이름 변경·가방 소모·수동 등록·추가 경기 횟수는 이번 범위에 포함하지 않는다. `data/itemList.json`은 변경하지 않았으며 Notion 본문도 유지한다. GM교육은 별도 시뮬레이션 후 수정안 대기다.
- `ㅁㅂ`/`ㅁㄱ`/`ㅁㅌ`는 굴리기/구매/통과의 정확한 별칭이다. 일반 명령의 제한과 쓰기 잠금·DEV 격리를 유지한다. 부길마는 모집 시작과 동일 명령의 정산 재시도만 가능하며 참가비 설정·모집 취소·중단은 길드마스터만 가능하다.
- 진행 안내와 게임판의 2메시지·각 전체보기는 유지한다. 현재 차례와 가능한 행동을 하단 한 곳에 표시하고, 선택 대기에는 이동한 사람을 유지한다. 반복 횟수/가이드 안내를 진행·정산에서 제거하고 게임판 소유자도 전체 참가자 닉네임으로 표시한다. 이동·이벤트 설명과 금액 결과를 구분하며 부족 통행료는 실제 지급액·부족액·파산을 안내한다. 가이드는 전체 규칙을 새 정책으로 교체했다.
- 통행료 Lv1은 75/120/150골드, Lv2는 3배이며 구매·건설비는 유지한다. 행운은 고정 +100골드, 기회는 기존 50% +200/-100골드다. 기존 경기/횟수 저장 형식과 회원·정산 복구 흐름은 유지한다.

## 구현 범위

- 길드마스터 모집/참가비 설정 → 같은 길드 4명 준비 → 시작 시 소속·잔액 재검증과 참가비 차감. 무작위 순서와 선공 골드 보정, 16칸·10라운드 정순/역순 게임.
- 구매·건설·통행료·이벤트·파산, 생존자 자산순/탈락 역순 정산. 동점 생존자만 한 번 추첨하고 결과 보존. 10% 수수료 제외 후 40/30/20/10% 지급.
- 실제 4명(탈락자 포함) 전원 동의 시 전액 환급. 유효한 진행은 중단 동의를 취소한다. 길드당 KST 하루 3회, 자정에도 현재 경기 유지, 타이머 없음.
- 기존 계정 ID 사용으로 닉변·탈퇴/추방 후에도 진행 가능. 삭제 뒤 같은 닉네임으로 생성된 다른 계정에는 상금을 지급하지 않는다.
- 조회/실패 입력은 무저장, 일반 턴은 소형 경기 파일만 저장. 포인트 변경은 기존 회원 저장과 경기 원문을 복구 기록으로 묶고 다음 명령에서 중단 게시를 먼저 복구한다.
- 기존 채크랭크의 오래된 길드 참조 정리가 경기 조회에서 회원 원본을 바꾸거나 저장하지 않도록 표시용 사본 사용.
- 정산 대기에서도 역할·참가비 범위 검사를 먼저 적용한다. 원래 방에서 길드마스터 `/마블시작`과 기존 참가자(탈락·탈퇴 포함) `/마블굴리기`만 미지급 재시도. 다른 행동·잘못된 인수·권한 없는 요청은 안내만 출력한다.

## 운영 시작

1. 운영자가 검증된 소스를 MessengerBot에 업로드·컴파일한다.
2. 길드마스터가 `/길드마블` 확인 후 필요하면 `/마블참가비 1`~`10`으로 설정하고 `/마블시작`을 입력한다.
3. 같은 길드의 실제 참가자 4명이 `/마블준비`. 길드마스터가 플레이하려면 본인도 준비한다.
4. 멈춘 게임은 `/마블판`, 규칙은 `/마블가이드`. 정산 대기는 계정/포인트 문제 해결 후 원래 방에서 `/마블굴리기` 또는 `/마블시작`으로 미지급만 재시도한다.

Android MessengerBot의 실제 메시지 표시와 기기 파일시스템은 운영자 확인 영역이다. 모든 자동 검증은 합성 계정과 로컬 임시 파일로 실행했다.
