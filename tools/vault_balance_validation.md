- 기획: [호월이의 금고털이 밸런스 개편 기획서](https://app.notion.com/p/03f393bdd7aa83f997e50193a3468d81), 상태 `🛠 READY`, 운영 반영예정일 `26.10.26` 확인.
- 기준 운영 소스: `2ca1f8867b36726ca2f595bf1bd9515d1432dc55` / `ver_2.707`.
- 반영 버전: `ver_2.708` / 2026-10-26.

## 구현과 검수 기준

- 일반·일반 호이패스 3회, 프리미엄 5회. 모든 금고가 개인 사용 횟수를 공유하며 같은 유저의 여러 금고 당첨을 허용한다.
- 1~3번째: 쉬움 100~999, 고정 2억, 최근 힌트 3개.
- 4~7번째: 보통 1000~9999, 고정 5억, 최근 힌트 5개.
- 8~10번째: 어려움 10000~99999, 고정 10억, 최근 힌트 5개.
- 지급 확정 후 다음 금고를 열고 힌트를 지운다. 범위가 바뀔 때 이전 비밀번호가 새 범위 밖이면 제외 대상으로 사용하지 않는다. 10개 총 지급액은 56억이며 이후 도전·운영자 리게임으로 연장하지 않는다.
- 제목 난이도, 순번, 현재 범위, UP⬆️/DOWN⬇️, 🔐숫자 형식, 최신순 힌트. 금일 당첨자(정답·닉네임·금액)는 최신순 allsee, 합계는 지급 완료 금액만 포함한다. 메뉴 프리미엄 추가 횟수는 +2회로 동기화했다.
- 실제 회차 전환은 기존 권한 확인된 `/리셋`만 사용한다. 자정 시각만 지나서는 초기화하지 않으며 이후에도 유효한 도전이 가능하다. 공개 안내의 관리자 명령어는 숨기고 자정으로 표시한다.

## 기존 데이터와 저장

- schema1/2와 기존 복구 저널을 먼저 검증·복구한 후 schema3으로 이관한다. 미당첨 이월 상금은 활성 금고에서 폐기하고 단계별 고정 상금으로 교체한다. 기존 원문 금고는 월별 보관에 남긴다.
- 현재 일일 회차의 기존 당첨과 사용 횟수를 보존한다. 같은 날짜에 이미 `/리셋`한 이전 회차의 당첨은 새 회차 목록에 다시 포함하지 않는다. 기존 확정 당첨의 금액·보상 ID·기지급 여부·미지급·공지 상태는 유지한다. 기존 미지급 확정 보상은 원래 금액을 정산하고 기지급 보상은 재지급하지 않는다.
- 구 진행에 일일 리셋 표식이 없으면 저장된 금고 날짜(없으면 밸런스 날짜)를 사용해 실제 `/리셋`을 기다린다. 시계 날짜로 임의 초기화하지 않는다.
- 기존 미니게임 지급 원장·원문 저널·회원 저장·월별 보관·중단 복구·게임 ID/요청 시각 검증·DEV/PROD 경로·7인수 콜백·잠금을 재사용한다. 새 스케줄러나 초기화 명령은 없다. 손상 파일을 기본값으로 덮어쓰지 않는다.
- 과거 지급 검증에 필요한 이전 숫자 범위/금액 상수만 `legacy` 설정에 남긴다. 활성 이월 상금 설정·계산 함수·노출은 제거했다. 이미 확정된 과거 보상 때문에 개편 당일 실제 지급 합계는 새 금고 10개만 진행한 56억 예시와 다를 수 있다.

## 운영 적용 범위

운영 반영은 검증된 소스 브랜치를 푸시하고 `feature/prod`에 반영한 뒤 원격 커밋·버전을 확인하는 범위다. Android 기기 업로드·컴파일·재시작은 운영자가 수행한다. 기기에서의 실제 실행 및 메모리 부족 재현은 미검증이다. 런타임 진행/회원/저널/보관 파일을 저장소 스냅샷으로 덮어쓰지 않는다.
